# Export fixture corpus

Each `vN/` directory holds JSON files produced by (or crafted to resemble) schema
version `N` of the vocabulary export format. `malformed/` holds hostile/invalid input.

## The one rule

**Fixtures are append-only and immutable.** Once a fixture file is committed, it is
never edited and never deleted. If a fixture test fails, fix the code — never the
fixture.

Editing an old fixture to make a test pass destroys the entire value of this system:
it converts "old data still works" into "the test agrees with itself." A CI guard
enforces this mechanically (see the release checklist / CI workflow).

Adding new fixture files is always fine. Regenerating a version's fixtures from the
writer that produced them (see `FixtureGeneratorTest`) is fine as long as the
regenerated bytes are identical to what's committed — if they differ, that's a sign
the writer changed and the *new* version's fixtures are what changed, not the old ones.
